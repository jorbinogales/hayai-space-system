# HAYAI --- Exportación del chat / Documento de continuidad

**Fecha de exportación:** 30 de septiembre / 1 de octubre de 2026\
**Proyecto:** HAYAI --- sistema interno / HAYAI CORE

------------------------------------------------------------------------

# 1. Contexto general de HAYAI

HAYAI es un proyecto formado por **3 socios** que se dedicará a
desarrollar **sistemas pragmáticos para clientes**, utilizando
herramientas como IA, Lovable y otras tecnologías.

El objetivo actual es construir **el sistema interno de HAYAI**, para
llevar el control de la propia empresa.

La aplicación debe permitir controlar:

-   Clientes.
-   Proyectos.
-   Pagos iniciales.
-   Pagos mensuales.
-   Pagos pendientes.
-   Ingresos.
-   Gastos.
-   Costos de cada sistema.
-   Rentabilidad por proyecto.
-   Tareas.
-   Reuniones.
-   Entregas.
-   Renovaciones.
-   Actividad interna.
-   Flujo de caja.
-   Próximos cobros.
-   Estado general de HAYAI.

La intención no es crear otro sistema administrativo genérico, sino una
experiencia que represente la forma en que HAYAI opera y entiende su
propio negocio.

------------------------------------------------------------------------

# 2. Problema detectado con la primera propuesta visual

La primera propuesta visual tenía una estructura típica de software
administrativo:

-   Sidebar izquierda.
-   Dashboard.
-   Tarjetas KPI.
-   Tablas.
-   Gráficos.
-   Módulos tradicionales.

Aunque era moderna, se identificó que visualmente parecía un **dashboard
SaaS / CRM genérico**.

La conclusión fue:

> HAYAI no debe parecer un ERP o CRM genérico.

El usuario indicó específicamente que:

> "No quiero que sea un sistema genérico, fíjate que ese layout visual
> es genérico."

Después se planteó abandonar la navegación tradicional con sidebar.

------------------------------------------------------------------------

# 3. Nueva idea conceptual

La dirección visual cambió hacia una **interfaz espacial e
interactiva**.

La idea principal:

> HAYAI no tiene que tener "módulos"; tiene que tener un espacio de
> trabajo.

El sistema debe sentirse como un **centro operativo visual de HAYAI**.

La interfaz debe representar relaciones entre:

-   Clientes.
-   Proyectos.
-   Finanzas.
-   Tareas.
-   Eventos.
-   Pagos.
-   Gastos.

En vez de presentar todo como módulos independientes, los elementos
deben estar conectados.

------------------------------------------------------------------------

# 4. Referencia visual dibujada por el usuario

El usuario proporcionó un boceto donde:

-   No existe una sidebar izquierda.
-   Existe un elemento central.
-   Alrededor del centro aparecen elementos/nodos.
-   Hay información contextual alrededor.
-   Existe una zona inferior destinada a un timeline.
-   La composición recuerda a un sistema espacial/orbital.

La idea visual fue descrita como:

> "algo interactivo, creativo y funcional"

y posteriormente se definió específicamente como una experiencia
inspirada en:

-   Planetas.
-   Lunas.
-   Órbitas.
-   Nodos.
-   Relaciones.
-   Movimiento.
-   Exploración.

------------------------------------------------------------------------

# 5. Concepto HAYAI CORE

El concepto seleccionado es:

## HAYAI CORE

Subconcepto:

> "Todo está conectado."

HAYAI CORE representa el centro operativo de la empresa.

El usuario no entra simplemente a "Clientes" o "Finanzas" como si fueran
páginas independientes.

Entra al CORE y desde allí explora la información.

El núcleo central puede representar:

**HAYAI**

Y alrededor:

-   CLIENTES
-   PROYECTOS
-   FINANZAS / GASTOS
-   TAREAS
-   EVENTOS

Estos elementos funcionan visualmente como planetas o cuerpos orbitales.

------------------------------------------------------------------------

# 6. Concepto de navegación orbital

La navegación debe ser espacial.

Ejemplo:

``` text
                 CLIENTES

        PROYECTOS       FINANZAS


                    HAYAI


          TAREAS        EVENTOS
```

Los elementos no deben sentirse como botones administrativos.

Deben sentirse como objetos interactivos.

Al seleccionar uno:

-   Se entra en ese contexto.
-   El centro cambia.
-   Aparecen sus entidades relacionadas.
-   Se puede continuar profundizando.

# 8. Interacción de los planetas

Los planetas deben poder seleccionarse.

La navegación debe sentirse como explorar un sistema planetario.

Al hacer clic sobre un planeta:

-   Se cambia de contexto.
-   El planeta seleccionado se convierte en el elemento central.
-   Sus elementos relacionados pasan a formar parte de la órbita.

Ejemplo:

## Entrar en CLIENTES

El planeta:

**CLIENTES**

pasa al centro.

Alrededor aparecen los clientes.

Ejemplo:

``` text
              TechSolutions

       EasyTech           Grupo Nova


                 CLIENTES


       Soluciones Lara    Innova Digital
```

Cada cliente es representado como un punto en el planeta

# 15. Rentabilidad de proyectos

Uno de los objetivos más importantes de HAYAI es saber:

> "En cuánto salió hacer ese sistema."

Por eso cada proyecto debe registrar:

-   Precio vendido.
-   Pago inicial.
-   Pagos recibidos.
-   Saldo pendiente.
-   Gastos directos.
-   Otros gastos.
-   Costos asociados.
-   Horas trabajadas, si se decide utilizar esta variable.
-   Costo interno por hora, opcional.
-   Costo total.
-   Utilidad.
-   Margen.

Fórmula conceptual:

``` text
UTILIDAD = INGRESO TOTAL - COSTOS
```

Y:

``` text
MARGEN = UTILIDAD / INGRESO TOTAL × 100
```

# 50. Resumen ejecutivo

HAYAI necesita una aplicación interna para gestionar:

**Clientes + Proyectos + Dinero + Tareas + Eventos + Pagos + Gastos +
Rentabilidad.**

Pero la solución visual elegida no es un CRM ni un ERP tradicional.

La aplicación será una experiencia tipo **sistema planetario
interactivo**:

``` text
                       CLIENTES
                          ○
                       /     \
              ○ PROYECTOS   ○ FINANZAS
                    \         /
                     \       /
                      ● HAYAI
                     /       \
               ○ TAREAS     ○ EVENTOS
```

Al entrar a CLIENTES:

``` text
                     Cliente A
                         ○

             Cliente B         Cliente C
                  ○               ○

                    ● CLIENTES

             Cliente D         Cliente E
                  ○               ○
```

Los clientes orbitan y pueden rotar.

Al seleccionar un cliente:

``` text
CLIENTE
│
├── Proyectos
├── Pagos
├── Gastos
├── Recaudación
├── Pendiente
├── Rentabilidad
└── Próximos pagos
```

Y debajo:

``` text
TIMELINE DE PRÓXIMOS PAGOS
●────────●────────●────────●────────●
```

El objetivo final es que HAYAI CORE no parezca un software
administrativo más, sino una **representación visual de cómo funciona
HAYAI como empresa**.
